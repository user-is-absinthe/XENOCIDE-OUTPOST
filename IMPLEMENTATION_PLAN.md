# XENOCIDE: OUTPOST — план реализации

Инструкции для агента-реализатора. Описывают следующую стадию разработки игры: что делать, в каком порядке, по каким правилам и с какими критериями приёмки. Документ самодостаточен: контекст и ограничения проекта повторены ниже.

---

## 0. Контекст и неизменные ограничения

Проект — самостоятельная однопользовательская semi-idle RPG в духе Soda Dungeon во вселенной XENOCIDE. Игровой цикл: база → найм → подготовка отряда → автоматическая экспедиция в заражённый комплекс «Гелиос» → эвакуация или поражение → добыча и развитие базы.

**Ограничения (нарушать нельзя):**

1. Целевая среда — Windows 10, Microsoft Edge, запуск двойным щелчком по `index.html`, включая `file://` и полностью без сети.
2. Никаких серверов, сетевых запросов, CDN, ES-модулей (`type="module"`, `import`/`export`), Python/Node у игрока, расширений и сторонних установок.
3. Классические локальные скрипты, глобальные имена вида `window.X = (() => {...})()` — как в существующих подсистемах (`progression.js`, `preparation.js` и т.д.).
4. Русский UI, управление мышью и клавиатурой. Стиль — мрачная научная фантастика: военная техника, промышленные заражённые зоны, ксеноморфы.
5. Оригинальный репозиторий XENOCIDE не изменять и не импортировать из него код. Заимствуются только мотивы и терминология.
6. Визуальная часть: Canvas 2D и локальный SVG, без внешних ресурсов (картинок, шрифтов, звуковых файлов). Звук — только генерируемый WebAudio.
7. Сохранение — `localStorage` + экспорт/импорт JSON. Никакой части симуляции по «настенным часам»: офлайн-прогресса нет, закрытая игра не продвигается.

**Процесс:**

- Тесты: `node tests/economy.cjs`, `node tests/interface.cjs`, `node tests/offline.cjs` — все должны оставаться зелёными; новые механики добавляют новые проверки туда же.
- Сборка: `powershell -ExecutionPolicy Bypass -File build.ps1` — пересобирает `dist/` и `XENOCIDE-OUTPOST-offline.zip`. После каждой законченной пачки изменений сборку обновлять, `node tests/offline.cjs` должен подтверждать совпадение `dist/` с исходниками.
- Коммиты: сообщение сначала по-русски, затем дублировать по-английски.
- Инструменты: Node/Python — только из окружения проекта (есть `.venv` Python, глобальный Node). Ничего глобально не устанавливать. OpenOffice/LibreOffice не использовать.
- Документацию (`README.md`, `ARCHITECTURE.md`, `GAME_DESIGN.md`, `PROGRESS.md`, `TESTING.md`) обновлять по мере реализации. `HANDOFF.md` — внутренний файл передачи контекста, в публичный репозиторий не добавлять (уже в `.gitignore`).

**Версии (приняты как есть, при реализации не пересматривать):**

| Артефакт | Версия |

| Схема сохранения (профиль) | `v3` (миграция из `v2`; восстановление повреждённых сейвов — не приоритет, совместимость желательна, но не обязательна) |

**Чего НЕ делать (явные запреты):**

- Prestige / перерождение — не реализовывать (допустимо в будущем, но не в этих пакетах).
- Испытания по seed / «ежедневные» забеги — не нужны.
- Глубокий слой снаряжения (боеприпасы, крафт, мастерская) — отложен, только упомянуть в документации как будущее.
- Баланс-тюнинг чисел (цены, урон, награды) — не пересматривать; все числовые константы только **вынести в одно место** (см. п. 1.2), чтобы вернуться к балансу позже по запросу пользователя.
- Монетизация, серверная часть, онлайн-функции, CDN, сборщики (webpack и т.п.) — запрещены.

## Пакет 1 — v0.4.0 «Раны и события»

Фундамент: честная механика здоровья, событийный бой, архитектурная чистка, статистика и «неяркая игра» в меню.

### 1.1. Модель ранений (приоритет №1)

**Убрать текущее поведение:** `crew` — копии объектов; при успехе HP рекрутов уменьшается на 8 (пол 45), при поражении не меняется; в-боевые ранения не переносятся на базу.

**Новое поведение:**

1. У бойца два числа: `maxHp` — вместимость здоровья, `hp` — текущее состояние (1…maxHp). Новый боец: `maxHp` = бросок при найме (как сейчас: платный 75–110 + бонус казарм, бродяга 55–70), `hp = maxHp`.
2. Высадка: в рейд уходит текущее `hp` (стартовое) и `maxHp` (потолок). Всё лечение в рейде (медик, аптечки, находки, медпост) восстанавливает только до `maxHp`.
3. Конец рейда (успех **и** поражение одинаково): для каждого выжившего `recruit.hp = hp` из отряда рейда (перенос ранений на постоянный ростер). Погибшие удаляются навсегда — как сейчас.
4. Лечение на базе, два канала:
   - **Медленное (бесплатное):** после каждого завершённого рейда все бойцы **на базе** восстанавливают `Progression.medbay(S.buildings.medbay).rest` HP (не выше `maxHp`).
   - **Платное:** в карточке бойца кнопка «Лечить» — восстанавливает до `maxHp` сразу. Цена: `ceil((maxHp − hp) / 2)` кредитов, со скидкой 5% за уровень медблока (итог округляется вверх, минимум 1 кредит). При полном здоровье или нехватке денег кнопка отключена.
5. Раненый боец может быть отправлен в рейд с любым `hp` — это риск игрока. Смерть в рейде постоянна.
6. Награды за риск: формулы наград **не менять** (баланс позже), но см. п. 1.2 — числа концентрируются в конфиге.

**UI:**

- Карточка бойца: полоса `hp / maxHp` (цвет: зелёный >60%, жёлтый 30–60%, красный <30%), стоимость лечения.
- Экран итогов рейда (см. п. 1.6): список изменений по каждому бойцу — «Ким-42: −37 HP (82 → 45)», «Орлов-31: погиб», «Вега-77: без изменений».

### 1.2. Архитектура и чистка кода

**Разбиение `game.js`** (глобальные имена, без модулей; существующие файлы не трогать по ответственности):

| Файл | Ответственность |
|---|---|
| `state.js` | схема профиля, `migrate`, save/load, экспорт/импорт JSON |
| `battle.js` | чистая симуляция боя без DOM: encounter, шаг, RNG, награды, события (см. п. 1.3) |
| `screens.js` (или `screens/*.js`) | HTML-разметка экранов: меню, база, отряд, рейд, итоги, настройки, графики |
| `input.js` | привязка обработчиков, удержание «Улучшить», горячие клавиши |
| `fx.js` | арена (бывший `arena.js`) и SVG-панорама базы (бывший `base-scene.js`) — можно оставить отдельными файлами, главное — не смешивать с логикой |
| `balance.js` | **единый конфиг числовых констант**: цены, награды, множители маршрутов, шанс находок, стоимость лечения, статы предметов, пороги опыта и т.д. |

Критерий: `battle.js` + `balance.js` + `state.js` должны работать в Node-тестах **без DOM-заглушек** (сейчас tests/economy.cjs эмулирует VM с DOM — после разбиения упростить до чистого require/eval без document).

**Уборка мёртвого кода:**

- В `game.js` два неиспользуемых определения `draw()` с собственными `marine`/`alien` — удалить (арену рисует `Arena.render`).
- Привязка `document.querySelectorAll('nav button')...` внизу `game.js` перекрывается `bind()` при первом `render()` — удалить.
- `render()` в конце рисует арену, а `animate()` рисует её же каждый кадр — оставить одну отрисовку (в `animate`).

**Производительность (частично):** на экране рейда не пересобирать весь DOM каждый тик — обновлять точечно динамические регионы (HP-полосы, журнал, счётчик шлюза, HUD). Каркас (канвас, кнопки) переиспользовать. Это убирает костыли `capture/restore` фокуса и «кнопка живёт в DOM во время серии покупок» (удержание станет штатным: обновлять текст кнопки и ресурсы без пересборки).

**Диалоги:** заменить оставшиеся `confirm()`/`alert()` («Новая игра», «Прервать экспедицию», ошибка импорта) внутренним диалогом с ролью `dialog`, модальным фокусом и кнопками — как уже сделано для шлюза и итогов.

### 1.3. Событийная модель боя и синхронизация арены

**Движок (`battle.js`)**

- Шаг боя `step(state)` возвращает **массив событий**; состояние изменяется только движком.
- Типы событий (минимум): `hit` (кто, цель, урон), `kill`, `heal` (кто, цель, сколько), `kit` (аптечка), `loot` (сумма, источник), `spawn` (новый враг), `sectorClear`, `bossPhase` (событие фазы босса), `grenade`, `retreat`, `cover`.
- RNG — как сейчас (LCG по `seed`), но **все** обращения к RNG — только внутри `battle.js`, в фиксированном порядке вызовов (детерминизм сохраняется и после загрузки checkpoint).
- Журнал боя — производная: каждое событие форматируется в строку одним форматтером (тесты проверяют события, а не разбор строк).

**Арена (`fx.js`) — подписчик событий**

- Арена получает очередь событий с таймингами и проигрывает: вспышка выстрела в момент реального `hit`, красная вспышка по получившему, всплывающее число урона над целью, анимация смерти по `kill`, зелёная вспышка по `heal`, подсветка находки по `loot`.
- Фоновая «жизнь» (покачивание, дыхание) остаётся на `visualTime`, но боевые визуальные эффекты — только от событий.
- Арена не меняет состояние боя и не использует его RNG (как сейчас — правило сохраняется).

### 1.4. Желание заказчика: неяркая версия игры в меню

В главном меню (`screen === 'menu'`) **за** панелью меню показывать живую игровую сцену, затемнённую до «неяркой» версии — как в оригинальном XENOCIDE.

- Реализация: демо-бой на арене (синтетическое демо-состояние отряда и врагов, цикл 20–30 секунд) либо спокойная анимация базы — поверх затемнение (яркость ~30–40%, например CSS `filter: brightness(.35)` или оверлей `#00000066`), `pointer-events: none`, без HUD и цифр.
- Демо не использует RNG игры, не трогает состояние и сохранения, отключается при `prefers-reduced-motion` (тогда — статичный тёмный кадр).
- Заголовок меню и кнопки остаются контрастными поверх затемнения.

### 1.5. `prefers-reduced-motion`

При `prefers-reduced-motion: reduce`: отключить покачивание/анимацию арены и демо в меню (оставить статичные кадры и мгновенные смены состояний). Проверить, что бой остаётся читаемым (числа и лог — на месте).

### 1.6. Экран итогов рейда

Расширить диалог итогов (победа и поражение):

- Пер-бойцовые изменения: HP до/после (см. п. 1.1), погибшие, начисленный опыт (см. пакет 2 — зарезервировать место).
- Разбивка добычи: «за бои», «тайники», «бонус эвакуации», «возврат припасов» (полные суммы, без сокращений — как сейчас).
- Потери: что не вернулось (аптечки при поражении и т.п.).
- Кнопка «Вернуться на базу →» — как сейчас.

### 1.7. Графики: сбор статистики и кнопка в меню

Отдельная кнопка в главном меню («Статистика» / «Графики») — экран с графиками, построенными вручную на Canvas (никаких библиотек):

1. **Смертность / глубина:** сколько бойцов погибло по диапазонам глубины.
2. **Кредиты / глубина:** средняя добыча за рейд по диапазонам глубины.
3. **Эвакуации и поражения / глубина:** соотношение успешных и неудачных завершений по диапазонам глубины.

**Сбор данных:** агрегаты в профиле, бакеты по диапазонам глубины (например, 1–4, 5–9, 10–14, … по 5 секторов):

```js
stats: { byDepth: { "1-4": { runs, evac, deaths, loot }, ... }, total: { runs, evac, deaths, loot, kills } }
```

Обновляются при каждом `finish()` и событиях `kill`. Данные копятся с этой версии (в старых сейвах графики пустые — допустимо). Сохранение ограничить размером: только бакеты, без истории рейдов.

Баланс по графикам **не** корректировать — только визуализация.

### 1.8. Миграция сохранения v2 → v3

- `migrate`: v2 → v3 добавляет `hp/maxHp`-модель (у существующих рекрутов `hp = maxHp` = текущее значение hp), `stats`, пустые слоты снаряжения (пакет 2 — поле зарезервировать), `seenStory: []`.
- Совместимость желательна: валидация с прежней строгостью, но при ошибке — **не** тихий сброс; минимум — сообщение в UI («сохранение нечитаемо, начата новая игра») вместо молчаливого `fresh()`. Полноценное восстановление повреждённых сейвов — вне объёма.
- Экспорт/импорт JSON оставить как есть.

## Пакет 2 — v0.5.0 «Бойцы и снаряжение»

### 2.1. Опыт, уровни, перки

- У бойца `xp`, уровни 1–5. Пороги (черновые, в `balance.js`): 0 / 100 / 250 / 500 / 900.
- Начисление при завершении рейда: `+10 × достигнутая глубина + 25 × число пройденных боссов (сектора кратные 5)`. Начисляется и выжившим, и (посмертно — нет, погибшим не начисляется).
- За уровень: `+3 maxHp`, `+1` к урону (постоянно, поверх бонусов казарм и арсенала).
- Ранг = уровень − 1 → `Progression.ranks` («Рекрут» … «Спецгруппа») — отображается в карточке (уже есть).
- **Перки:** на уровнях 2 и 4 — выбор одного перка (внутренний диалог после итогов рейда; если пропущен — выбор доступен в карточке бойца). Максимум 2 перка у бойца. Пул перков:

| Перк | Эффект |
|---|---|
| «Крепкий» | +15 maxHp |
| «Меткий» | +2 урона |
| «Полевой медик» | +8 к лечению отряду (для класса медик — к лечебному ходу) |
| «Бронированный» | +2 брони |
| «Искатель» | +5% к шансу находок (тайник/медицина) |
| «Ветеран» | +1 урона за каждые 5 секторов текущего рейда |

Смерть — постоянна (перки и опыт погибшего уходят вместе с ним).

### 2.2. Снаряжение: минимальный + средний слой

**Минимальный слой:**

- Предметы получают определения: `id, name, type (weapon|armor|gadget), effects, durability, classReq` (опционально).
- У бойца `gear: { weapon, armor, gadget }` (ссылки на id предметов из инвентаря базы `S.items`). Один предмет — один владелец; выдача/снятие в карточке бойца (блок «Снаряжение» во вкладке «Отряд»).
- Эффекты применяются к статам при высадке (снимок в `raid.crew`, как аптечки): `atk = база + перки + оружие + …`.
- **Износ:** после каждого рейда у экипированных предметов −1 прочность (старт 10, минимум 0). Прочность 0 — эффект не действует («сломан»). Починка в карточке: 5 кредитов за единицу прочности.

**Средний слой:**

- Слоты (оружие / броня / гаджет) — как выше.
- Особые свойства: «Энергетический аккумулятор» — +4 урона только инженеру; «Страховой маяк» — при смертельном ударе боец остаётся с 1 HP, маяк расходуется (не более одного спасения за рейд).
- **Дроп:** босс (сектор, кратный 5) — гарантированно случайный предмет; тайник — 25% шанс предмета; награда контракта (пакет 3) может давать предмет.
- Стартовый инвентарь — текущие 12 названий. Таблица определений (числа черновые, в `balance.js`):

| Предмет | Тип | Эффект | Прочность |
|---|---|---|---|
| Импульсная винтовка | оружие | +3 урона | 10 |
| Карабин МК-2 | оружие | +2 урона | 12 |
| Экспериментальный плазморез | оружие | +5 урона, −1 брони владельцу | 8 |
| Бронепластина | броня | +2 брони | 10 |
| Полевой медкомплект | гаджет | +5 к лечению аптечками | 10 |
| Осколочная граната | гаджет | активная кнопка в бою: 15 урона всем живым врагам, раз за бой | 1 (расходник) |
| Энергетический аккумулятор | гаджет | +4 урона, только инженер | 10 |
| Автотурель «Оса» | гаджет | +3 урона | 10 |
| Сканер биомассы | гаджет | +5% к шансу находок в рейде | 10 |

### 2.3. Решения в бою

1. **Кнопка над ареной** (правый верхний угол канваса или панель над ним): «Граната» — активна, если у кого-то из отряда экипирована граната; жмётся один раз за бой; событие `grenade` в журнале и на арене (вспышка по всем врагам).
2. **«Отступить»** (в панели действий рейда, любой момент боя): внутреннее подтверждение → рейд завершается как «отступление»: выжившие возвращаются с ранениями, груз = 50% текущего (постоянная в `balance.js`), аптечки не возвращаются, `run++`, глубина засчитывается. Отдельный исход в итогах.
3. **«Прикрыть отход»** (тёмная опция, доступна при 2+ живых, один раз за рейд): выбирается самый раненый боец (или указанный игроком) — он погибает, остальные немедленно завершают рейд с 100% груза (эвакуация успешна). Внутреннее подтверждение с предупреждением о гибели. В итогах — причина смерти.

## Пакет 3 — v0.6.0 «Контент»

### 3.1. Контракты

- До 3 активных контрактов (`S.contracts`). Выдаются автоматически при возврате на базу (или кнопка «Взять контракты» на базе — на выбор реализатора, но без ручного «магазина квестов»).

- Награда: кредиты (50–150) или предмет. Выполнение — снятие контракта, выдача нового.
- UI: панель «Контракты» на базе (прогресс-полосы, награда).

### 3.2. Сюжетные вставки (небольшие)

- `story.js`: 6–8 текстовых вставок по вехам глубины (5, 10, 15, 20, 25, 30 секторов: первый контакт с Маткой, сигнал с «Гелиоса», эвакуационные протоколы и т.п. — тон: мрачная НФ, 2–3 предложения каждая).
- Показ при достижении вехи (диалог после зачистки шлюза или после эвакуации). `S.seenStory` — массив показанных id, без повторов.
- Согласовать термины с `GAME_DESIGN.md` («Ковчег», «Гелиос», «КОРПУС ВНЕШНЕЙ ОБОРОНЫ»).

### 3.3. Механики врагов и боссов

- **Матка (босс):** фаза на 50% HP — призывает 2 Личинок (событие `bossPhase`, фраза в логе).
- **Узел гнезда:** каждые 3 хода спавнит Личинку (максимум 3 живых личинки одновременно), событие `spawn`.
- **Плевальщик:** каждый 3-й ход бьёт самого раненого бойца (минуя «тяжёлого»), а не случайного.
- **Панцирник:** цели атак бойцов по умолчанию предпочитают Панцирника (если приказ не задан иначе); его броня действует как сейчас (пробитие арсенала).
- Личинка, Ползун — без изменений. Элита — как сейчас (множители + отметка).

### 3.4. Модификаторы комнат

Сектора, начиная с глубины 3 (не босс), с шансом 20% получают модификатор (выбор детерминирован seed):

| Модификатор | Эффект |
|---|---|
| «Радиация» | в конце каждого хода все живые бойцы −2 HP (не ниже 1) |
| «Споры» | всё лечение в секторе −50% |
| «Агрессивная среда» | враги +15% урона, награды за бой +15% |

Плашка в HUD рейда: «МОДИФИКАТОР: …». Действует до конца сектора, не влияет на уже собранный груз.

### 3.5. События с выбором в комнатах

После зачистки обычного сектора (не шлюз) с шансом 20% — диалог с выбором (останавливает тик, работает пауза, `overlay='event'`):

| Событие | Варианты |
|---|---|
| «Запечатанный контейнер» | Вскрыть: 40% — бой с элитным врагом, при победе +50% к находке сектора; Пройти мимо: ничего |
| «Радиостанция» | Вызвать поддержку: +1 аптечка (если есть место в запасе); Молчать: ничего |
| «Обходной тоннель» | Пройти тоннелем: пропустить следующий сектор (глубина +1 сразу, без наград за него); Основной путь: как обычно |

Не более одного выбора за сектор. Детерминировано по seed (порядок расходования RNG — фиксированный).

## 5. Требования к коду и тестам (общие)

1. `battle.js` тестируется в чистом Node: шаги боя, события, детерминизм по seed, перенос ранений, механики врагов/боссов, модификаторы, события с выбором, граната/отступление/прикрытие.
2. `state.js` тестируется: миграция v1→v2→v3, корректные значения по умолчанию для старых сейвов, экспорт/импорт.
3. `tests/interface.cjs` — обновить DOM-заглушки под новые экраны: карточка лечения, слоты снаряжения, диалоги перков/событий, кнопка «Графики», экран итогов со списком изменений.

5. Экранирование пользовательских строк (функция `h()`) сохранять; доступность диалогов (роли, фокус-ловушка, `aria-pressed`) — расширять на новые.
6. `build.ps1` — обновить список файлов, если появятся новые (`balance.js`, `sound.js`, `story.js`, …): и в `dist/`, и в ZIP.
7. После каждого пакета: `node tests/economy.cjs && node tests/interface.cjs && node tests/offline.cjs`, затем `build.ps1`. Обновить `PROGRESS.md` и `TESTING.md`.
